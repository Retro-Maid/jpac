# 市区町村の廃置分合 → 公式データで裏づける（preflight）

`overrides/municipality_lineage.yml` は、市区町村コードの遷移を**人が署名して**書いている
ファイルである。identity 規則 I3（`docs/IDENTITY_MODEL.md`）はここに載った遷移でしか
発火しない。この文書は、その各行を**発行元の公式データで機械的に裏づける**ための
取得元・形式・実測を記録する。

ライセンスの判断は `docs/LICENSE_REVIEW_LINEAGE_2026_09.md`。人の確認は同 §1 であって、
この文書ではない。

結論を先に書く。

- **主ソースは e-Stat「廃置分合等情報を探す」の CSV**（総務省統計局）。1970-04-01 以降の
  廃置分合を、旧→新の5桁コードつきで持つ。
- **副ソースは総務省「全国地方公共団体コード」の団体コード表**。現行コードの集合の照合に
  使う。改正一覧表は人が読むための体裁で、旧→新の対応を列として持たないため主にしない。
- **yml の6遷移は、6件すべてが e-Stat の生データから完全一致で再現できた**（旧コード・
  新コード・施行日）。分割した旧浜松市北区（221350）も、承継先2件と区域の注記ごと取れる。
- **yml を置き換えるのではなく、yml の各行を検査するゲートとして使う**のが最初の一歩。

## 1. 取得元

### 1.1 e-Stat 廃置分合等情報（主）

| | |
|---|---|
| ページ | <https://www.e-stat.go.jp/municipalities/cities/absorption-separation-of-municipalities> |
| 取得方法 | 検索フォームを GET し、`op=download&file_format=csv&charset=UTF-8&bom=0` を付ける。API ではなく画面のダウンロード機能 |
| 期間 | 1970-04-01 以降（検索範囲の終端を 2028-12-31 にすると、公表済みの将来施行分も入る） |
| 件数（2026-09-27 実測） | 3,739行（境界変更を除く）／ 11,663行（境界変更を含む） |
| 再現性 | 同じ URL を2回取得して SHA-256 が一致。ファイル名の時刻部分だけが毎回変わる |
| 更新頻度 | 公表されていない |

列（13）: 事由パターン, 支庁・振興局等内郡, 同ふりがな, 標準地域コード(5桁), 都道府県,
政令市･郡･支庁･振興局等, 同ふりがな, 市区町村, 同ふりがな, 廃置分合等施行年月日,
改正事由, 告示年月日, 告示番号

```
"編入合併","","","14422","神奈川県","津久井郡","つくいぐん","津久井町","つくいまち","2006-03-20","津久井町(14422)、相模湖町(14423)が相模原市(14209)に編入","2005-08-12","887"
"区の再編","","","22135","静岡県","浜松市","はままつし","北区","きたく","2024-01-01","浜松市（22130）の区の再編　北区（22135）（三方原地区以外）、浜北区（22136）を浜名区（22139）に再編","2023-02-22","5"
```

**旧→新のコードは、改正事由の本文に「名称(5桁コード)」の形で書かれている。**
名称で推測する必要が無い、というのがこのソースを主にする理由である。

事由パターンは16種で、1:N（分割・分離・政令市移行で区ができる場合）、N:1（合併）、
編入と新設の区別、名称変更、町→市でコードが変わる場合を区別できる。

同じサイトの「市区町村を探す」（`/municipalities/cities/areacode`）は、任意の時点で有効な
コード一覧を返す。コードの有効期間の照合に使える。

### 1.2 総務省 全国地方公共団体コード（副）

| | |
|---|---|
| ページ | <https://www.soumu.go.jp/denshijiti/code.html> |
| 団体コード表 | `000925835.xlsx`（R6.1.1現在）。6桁コード・都道府県名・市区町村名・カナ |
| 改正一覧表 | `000875488.xlsx`（平成17年4月1日以降） |
| 仕様書 | `000137948.pdf`（検査数字の計算式、コード付番の規則） |

団体コード表は **1,965件 = jpac の `municipality` 1,918件 + 都道府県47件で完全一致**した。

改正一覧表は、結合セル・「〃」・「同左」、日付の書式の混在（datetime／Excel シリアル値／
元号文字列）があり、旧→新の対応は列ではなく「合併後は」の文章として行をまたいで書かれて
いる。体裁の不整合も実際にある（横芝光町・香美町の新設行で改定区分が空欄、栃尾市の
改定区分が「削除」）。**照合には使えるが、系譜の主ソースにはしない。**

### 1.3 採らないもの

- 総務省「市町村合併資料集」の合併日順一覧：名称だけでコードが無く、平成11年以降に限られる

## 2. 実測（2026-09-27）

### 2.1 yml との照合

| | 結果 |
|---|---|
| `transitions` 6件 | **6/6 完全一致**（旧コード・新コード・施行日・承継先1件） |
| `unlisted` の 221350（旧浜松市北区） | 221384／221392 の2件に分かれ、区域の注記付き（「三方原地区/初生町…」と「三方原地区以外」）。yml の記述と一致 |
| 食い違い | 無し |

### 2.2 コード集合の照合

| | 結果 |
|---|---|
| jpac 現行 1,918件 vs e-Stat「市区町村を探す」2026-09-27 時点 | jpac にだけあるもの 0件。e-Stat にだけあるのは 13100（特別区部。集計用コード）1件 |
| jpac 1,918件 vs 総務省 団体コード表 | 完全一致 |
| e-Stat 2020 小地域の市区町村コード 1,897件 vs 2020-10-01 時点の一覧 | 1,896件が存在。無いのは 13199（`unassigned_area`。市区町村コードとして実在しない）だけ |
| jpac が superseded / split として扱う 22131〜22137 | 全件が 2020 時点の一覧にあり、廃止日は 2024-01-01。系譜で現行コードまでたどれる |

### 2.3 e-Stat と改正一覧表の突き合わせ（2005-04-01〜2024-01-01）

「コード＋日付＋欠番/新設」の単位で、改正一覧表の 1,184件は **100% e-Stat にもあった**。
e-Stat にだけある 155件は、すべて理由がついた。

- 115件：合併でコードを引き継いだ新設（改正一覧表では「同左」）
- 28件：支庁のコード
- 8件：同じコードのまま名称変更した市（常総・蓮田・妙高・丹波篠山）を、e-Stat は
  廃止＋新設として記録している
- 4件：改正一覧表側の体裁の不備

### 2.4 規則ベースの抽出

事由パターンごとの規則で改正事由を読み、旧→新の辺を作った。名称による照合はしていない。

- 3,739行中 **3,735行を解析**、辺は 2,525本
- 承継先の候補数：1件が 2,062本、2件以上が 109本（政令市移行で区ができる 81、
  分割・分離 12、浜松北区 2 など）
- **未解決の4行**：上九一色村の分割編入（2006-03-01、大字ごとに甲府市と富士河口湖町へ
  分かれた）。同じ節に書かれているため、1:1 の 中道町(19326)→甲府市(19201) も今は
  未解決に巻き込まれている
- 厳密化する前は 19201→19430 という**誤った辺が生成されていた**。「名称(コード)」の並びとして
  厳密に読めない節は辺にしない、という規則が要る実証である
- 新設／廃止フラグ（フォームの絞り込みで取り直せる）との双方向照合で、期待と違ったのは
  3件だけ（同じ日に編入と名称変更が重なった例で、説明がつく）

### 2.5 検査数字

`cd = (11 - Σ(d_i × [6,5,4,3,2]) mod 11) mod 10`。仕様書の注記（余り0→1、余り1→0）と一致し、
jpac 1,918件・団体コード表 1,965件のいずれも 100% 一致した。e-Stat は5桁しか持たないので、
6桁の `lg_code` にはこの式で検査数字を付ける。

## 3. 危ういところ

1. **分割・分離・政令市への移行は、承継先が一意にならない。** 候補が2件以上なら I3 は
   発火させない、という既存の方針のままでよい。
2. **分離と編入では旧コードが存続する。** 存続側の辺（old→old）を明示しないと、候補数が
   実際より少なく数えられる。
3. **政令市への編入は、区単位の承継先が書かれていない**（旧岩槻市→岩槻区、旧五日市町→
   佐伯区）。親市のコードまでしか確定しない。
4. **大字単位の分割編入**（上九一色村）は機械的には解けない。未解決のまま保持する。
5. **valid_from に使えるのは施行年月日だけ。** 告示年月日は行ごとに違う。
6. **CSV はリクエストのたびに生成される。** 取得したクエリ URL と SHA-256 を記録する。
7. **e-Stat の廃止日は「その日を含まない」終端。** 22131 は 2023-12-31 時点で有効、
   廃止日は 2024-01-01。
8. **全列が同じ行が2組ある**（29321 と 11238 の名称変更）。行のハッシュだけを主キーに
   すると取りこぼす。
9. **登録日を確認できていないコードがある。** 北方領土6村（01695〜01700）は 1970年・1983年の
   時点の一覧に無く、新設のイベントも無い。
10. **yml のコメントの誤り**：「改正一覧表は R5.4.1 時点で浜松の再編を含まない」とあるが、
    2026-09-27 に取得したファイル（Last-Modified 2025-01-22）には R6.1.1 の浜松の行が
    入っていた。見出しは「R5.4.1時点」のまま、同じ URL で差し替えられたと見られる。
    実装時にコメントを直す。

## 4. 出すもの（案）

| テーブル | 中身 |
|---|---|
| `municipality_change_raw` | CSV の1行 = 1行。削除しない。13列を `*_raw` で保持。主キーは `(source_snapshot_id, row_ordinal)`。`row_sha256` は持つが主キーにしない。`parse_status`（parsed / unresolved） |
| `municipality_lineage_edge` | 旧→新の辺。`effective_date`, `old_lg_code`, `new_lg_code`（NULL 可）, `event_type`, `area_qualifier_raw`, `parse_rule_id`, `source_row_ordinals`, `candidate_count`, `is_unique_match` |
| `municipality_code_registry` | 「市区町村を探す」の時点一覧から作るコードの有効期間。`valid_to` は含まない終端 |

- 境界変更・郡・支庁・都市種別変更の行は、辺にしない（raw 層には残す）。
- 同じ辺が複数の行から出る場合は1本にまとめ、出どころの行番号をすべて持たせる。

### I3 との関係

**yml を即座に置き換えない。** 最初は、yml の各行について「edge テーブルに候補1件で存在
すること」をビルドで確かめるゲートにする。

- 存在しない、または候補が2件以上なら、ビルドを止める（人の署名と公式データが矛盾して
  いるので、どちらかが誤っている）。
- yml に無い辺を I3 に使うかどうかは、この検査を何リリースか回してから別に判断する。

---

## 5. しないこと

- 名称だけで旧→新を結ばない（改正事由のコードが読めない節は未解決にする）。
- 分割の承継先を1つに決めない。
- 大字単位の分割（上九一色村）を推測で解かない。
- 改正一覧表の文章から対応を読み取らない（副ソースは集合の照合だけに使う）。
