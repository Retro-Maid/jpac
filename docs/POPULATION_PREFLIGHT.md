# 人口 → 国勢調査 令和7年 人口等基本集計（preflight）

jpac に人口を載せるための取得元・形式・実測を記録する。ライセンスの判断は
`docs/LICENSE_REVIEW_POPULATION_2026_10.md`、人の確認は同 §1 であって、この文書ではない。

結論を先に書く。

- **主ソースは e-Stat の令和7年国勢調査 人口等基本集計（原数値）**（総務省統計局、
  2026-09-29 公表）。全数調査で、基準日は 2025-10-01。
- **市区町村の 1,918件のうち 1,912件が、5桁の地域コードと `municipality.jis_city_code` で
  完全一致した。** 残る6件は北方領土の6村で、国勢調査の対象外。推測で埋めずに NULL として
  理由を残す。
- **表の内側の整合は全行で取れた**（男+女=総数、一般世帯+施設等の世帯=総数、区の合計=
  政令市、市区町村の合計=都道府県、都道府県の合計=全国）。そのまま品質ゲートにできる。
- **面積（参考）と人口密度は載せない。** 面積は国土地理院「全国都道府県市区町村別面積調」に
  よると表の注記に書かれていて、人口密度はその面積から算出されている。国土地理院を原典に
  掲げるデータは採らない、という既存の判断に合わせる。
- **市外局番の番号区画単位の人口は、582区画のうち301区画（全国の人口の 35.4%）で確実に
  出せる。** 市区町村を丸ごと含む区画だけ。残りは NULL として理由を残す（按分しない）。
- **形式は Excel（xlsx）だけ。** CSV は無い。「DB」は API の画面で、e-Stat 利用規約の別紙で
  別のルールになっているので使わない。

## 1. 取得元

| | |
|---|---|
| 統計 | 国勢調査（政府統計コード 00200521）令和7年 |
| 集計 | 人口等基本集計 ／ 集計結果（原数値）。212ファイル |
| 一覧 | <https://www.e-stat.go.jp/stat-search/files?tstat=000001230925&toukei=00200521&cycle=0&tclass1=000001230926&tclass2=000001232187> |
| 取得方法 | `https://www.e-stat.go.jp/stat-search/file-download?statInfId=<ID>&fileKind=0`（画面のファイルダウンロード。API ではない） |
| 公開日 | 2026-09-29 |
| 基準日 | 2025-10-01（調査の期日。`valid_from` に使えるのはこれだけ） |

### 1.1 第1段で使う表

| 表 | statInfId | ファイル | bytes | sha256 |
|---|---|---|---:|---|
| 第1-1表 男女別人口、世帯の種類別世帯数及び世帯人員 ほか（市区町村、2000年市区町村を含む） | `000040506423` | `b01_01.xlsx` | 809,971 | `c1ff781e05af6fce6510ee9cfbeba856106c97ae780ca030a549466b0074d856` |
| 第2-7表 男女、年齢（5歳階級及び3区分）、国籍総数か日本人別人口 ほか（同上） | `000040506431` | `b02_07.xlsx` | 8,606,864 | `3d0dab20893d8fca43ef33d521a0651841de105cf5b2720582e5024469030e75` |

第1-1表は2回取得して SHA-256 が一致した（2026-10-12）。上の値は下読みの観測であって、
受け入れのときには取得側が改めて計算する。

### 1.2 採らないもの

- **参考表：不詳補完値**（423ファイル）。統計局が「不詳」を補完した推計値で、jpac の
  「推定値を持たない」方針（按分しない、と同じ理由）に合わない。原数値は「不詳」を
  独立の区分として持つので、それをそのまま持つ。
- **DB（API）形式**。e-Stat 利用規約の別紙で「API 機能の利用について」は別ルール。
- **人口集中地区（DID）の表**（1-2 表など）。区域が市区町村と一致しないので、第1段では扱わない。
- **外国人を「総数 − 日本人」で作ること**。表に無い値を引き算で作らない。

## 2. 表の形

### 2.1 第1-1表

- シート1枚、4,097行 × 25列。0〜8行目が表題と注記、9〜13行目が表頭（表章項目・事項名・
  項目名・階層レベル・表章単位）、14行目が列名、15行目からがデータ（4,082行）。
- 列: 地域識別コード, 2000年_都道府県, 2000年_地域コード, 2000年地域, 2025年_都道府県,
  2025年_地域コード, 地域名, 人口（総数・男・女）, 2020年の人口（組替）, 5年間の人口増減数,
  同増減率, 人口性比, **面積（参考）**, **人口密度**, 世帯数（総数・一般世帯・施設等の世帯）,
  2020年の世帯数（組替）, 5年間の世帯増減数, 同増減率, 世帯人員（総数・一般世帯・施設等の世帯）
- **注記（3〜8行目）も意味を持つ。** 面積の出どころ（注5）や組替の定義（注1）が書かれて
  いるので、期待スキーマには表頭だけでなく注記の行も含め、変われば止める。

地域識別コード（ユーザーズガイド §3(4)）:

| コード | 地域 | 行数 | 扱い |
|---|---|---:|---|
| `a` | 全国・都道府県 | 48 | 集計行。`lg_code` に結ばない。整合の検査に使う |
| `1` | 東京都特別区部・政令指定都市 | 21 | 政令市20件は `lg_code` に結ぶ。特別区部（13100）は jpac に無い集計行 |
| `0` | 東京都23区・政令市の区 | 194 | `lg_code` に結ぶ |
| `2` | 政令市以外の市 | 772 | `lg_code` に結ぶ |
| `3` | 町村 | 926 | `lg_code` に結ぶ |
| `9` | 2000年（平成12年）時点の市区町村 | 2,121 | 2025年の値を2000年の境域に組み替えたもの。`lg_code` に結ばず、raw 層にだけ残す |

### 2.2 第2-7表

- 24,504行 × 48列。データは 24,492行 = 4,082地域 × {国籍総数, うち日本人} × {総数, 男, 女}。
- 年齢は 0〜4歳から100歳以上までの21区分と「年齢『不詳』」、再掲（15歳未満など）と構成比。
- **全行で、21区分 + 不詳 = 総数 が成り立った。** 不詳を落とすと合計が合わなくなる。

### 2.3 記号

ユーザーズガイド §3(1)「統計表中に使用されている記号等」:

| 記号 | 意味 |
|---|---|
| `-` | 該当数値がないもの |
| `0.0` | 単位未満の数値であるもの |

第1-1表で `-` が出るのは2か所だけだった。

- **施設等の世帯の世帯数・世帯人員**（82行。現行の町村22、2000年の市区町村60）：施設等の
  世帯が無い地域。0 として
  扱うと、総数 = 一般世帯 + 施設等の世帯 が全行で成り立つ。
- **双葉町の2020年の人口・世帯数（組替）と増減率**：2020年は全町避難で該当数値が無い。
  増減率は計算できない。

秘匿の `X` は、この2表には無かった（小地域集計にはある）。

## 3. 実測（2026-10-12）

### 3.1 jpac の市区町村との照合

| | 件数 |
|---|---:|
| 国勢調査の地域コード（`9` を除く） | 1,961 |
| うち jpac の現行 `municipality` に一致 | **1,912** |
| うち集計行（全国・都道府県 48、特別区部 1） | 49 |
| jpac にあって国勢調査に無い | 6（北方領土の色丹村・泊村・留夜別村・留別村・紗那村・蘂取村） |
| 重複した地域コード | 0 |

照合は `municipality.jis_city_code`（5桁）で行う。検査数字を自分で計算して6桁にしない。

### 3.2 表の内側の整合

| 検査 | 不一致 |
|---|---:|
| 人口: 男 + 女 = 総数 | 0 |
| 世帯数: 一般世帯 + 施設等の世帯 = 総数（`-` は 0） | 0 |
| 世帯人員: 同上 | 0 |
| 政令市・特別区部の区の合計 = 親 | 0 |
| 都道府県ごとの市区町村の合計 = 都道府県 | 0 |
| 都道府県の合計 = 全国（122,972,528人） | 0 |
| 第2-7表: 年齢21区分 + 不詳 = 総数 | 0 |

### 3.3 番号区画（市外局番）単位の人口

`bridge_municipality_telephone`（2,153行、582区画）で、**区画に属する行がすべて
`relation_type = child`（市区町村を丸ごと含む）** の区画だけが、市区町村の人口の和として
確実に出せる。

| | 区画数 | 人口 |
|---|---:|---:|
| 確実に出せる | **301** | 43,558,529（**35.4%**） |
| うち、政令市の親と区が両方載る区画（親の値だけを使う） | 6 | |
| 出せない（一部だけを含む市区町村がある） | 281 | NULL と理由を残す |

政令市は、jpac の `municipality` に親と区の両方が載っている。両方を足すと二重に数えるので、
親が丸ごと含まれる区画では親の値だけを使う（区の合計 = 親 であることは 3.2 で確かめた）。

愛知県の試算（17区画のうち10区画）と同じ傾向が全国でも出た。

## 4. 危ういところ

1. **政令市の二重計上。** 親と区の両方が jpac にある。合計するクエリが静かに二重に数える。
   出力に地域識別コード（階層）を持たせ、README でも注意する。
2. **2020年の組替値は、統計局が2025年の境域に組み替えた公式の値。** jpac の按分ではない
   ので載せてよい。ただし、すでにある `estat_small_area`（2020年の小地域）とは別物で、
   混ぜない。列名に年を入れる。
3. **調査年を混ぜない。** 令和7年の小地域集計は 2027年3月までに公表予定。郵便番号単位の
   再計測はその後に行う（2020年の小地域と2026年の ABR を名称で結ぶ方法では、確実な値が
   実用にならないことを愛知で確かめている）。
4. **基準日と取得日を混ぜない。** `valid_from` は 2025-10-01。取得日は `observed_from`。
5. **Excel を読む手段が依存に無い。** `xlrd` は旧形式（xls）用で、xlsx は読めない。xlsx は
   ZIP と XML なので、標準ライブラリ（`zipfile` と `xml.etree`）で読むのが第1案。
   依存を足すなら `docs/ARCHITECTURE.md` §5 に理由を書く。
6. **ファイルは同じ statInfId で差し替えられうる。** 確報で数値が直るときは、SHA-256 の
   変化として止まる。そのときは差分を確かめてから受け入れる。

## 5. 出すもの（案）

| テーブル | 主キー | 中身 |
|---|---|---|
| `census_population_raw` | `(source_snapshot_id, table_id, row_ordinal)` | 第1-1表の1行 = 1行。地域識別コード・地域コード・地域名と全セルを `*_raw` の文字列で持つ。`9` と `a` の行も消さない。面積と人口密度の列は持たない |
| `census_population_municipality` | `(census_year, lg_code)` | 1,918行。人口（総数・男・女）、世帯数（総数・一般・施設等）、世帯人員（同）、2020年の人口と世帯数（組替）。`area_level`（地域識別コード）。北方領土の6行は値を NULL にし、`value_status = 'not_enumerated'` |
| `census_population_age` | `(census_year, lg_code, nationality, sex, age_class)` | 第2-7表を縦持ちに。年齢21区分と不詳。再掲と構成比は持たない（区分から再計算できるので） |
| `census_population_numbering_area` | `(census_year, numbering_area_code)` | 582行。確実な301区画だけ値を持ち、残りは NULL と `value_status = 'partial_municipality'` |

- 値の列は整数。`-` は §2.3 のとおり、件数では 0、率では NULL。元の文字列は raw 層に残る。
- `census_year` は 2025。将来の国勢調査は行を足し、上書きしない。

---

## 6. しないこと

- 按分しない（面積比・点数比・世帯比のどれでも）。
- 不詳補完値を使わない。
- 2000年の市区町村（`9`）の行を、現行の `lg_code` に結ばない。
- 外国人を引き算で作らない。
- 面積・人口密度を載せない。
