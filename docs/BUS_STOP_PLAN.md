# バス停留所 → 市区町村

国土数値情報 **P11 バス停留所（令和4年度版）** を、e-Stat 国勢調査 小地域境界（2020年）で
市区町村に結ぶ。`docs/STATION_JOIN_PLAN.md` と `docs/RAILROAD_LINE_PLAN.md` の兄弟にあたる。

ライセンスの判断は `docs/LICENSE_REVIEW_P11_2026_09.md`。人の確認は同 §1 であって、この
文書ではない。要点だけ再掲する: **令和4年度版のみを使う。** 平成22年度版は「非商用」で
複製物の再配布が除外されており、N07 バスルートも全版が同じ条件なので、どちらも取得しない。

---

## 1. 出すもの

| テーブル | 行数 | 中身 |
|---|---:|---|
| `p11_bus_stop` | 278,515 | バス停留所。名称・事業者・都道府県 |
| `bridge_bus_stop_municipality` | 278,525 | バス停 ↔ 市区町村 |

粒度は市区町村で止まる。`address_id` 列は無く、あってはならない（`POLICY.md` §3.1）。

## 2. バス停には鍵が無い

これがこのデータで一番大きな設計上の制約である。駅には発行元のグループコード
`N02_005g` があり、路線には一意な `(路線名, 運営会社)` があった。**バス停にはどちらも無い。**

令和4年度版で実測:

| | |
|---|---:|
| バス停 | 278,515 |
| distinct `(バス停名, 事業者名)` | 276,169 |
| 複数のバス停が共有する組 | **2,035** |
| 最大の重複数 | 10（「住宅前 / 神奈川中央交通（株）」） |
| distinct `(名称, 事業者, 座標)` | 278,503（なお **12組が重複**） |

当初の見込みは「同名は上り/下りのペアだろうから名前で集約できる」だった。**測って否定された。**

| 重複グループ内の最大距離 | |
|---|---:|
| 中央値 | **16,369 m** |
| p90 | 55,286 m |
| 最大 | 577,478 m |
| 50 m 以内に収まるグループ | 31 (1.5%) |
| 5 km 以内に収まるグループ | 558 (27.4%) |
| **県をまたぐグループ** | **129** |

衝突の大半は「近接する対のバス停」ではなく、**遠く離れた別のバス停が同じ名前を持っている**
だけである。名前で集約すれば中央値16km離れた別々のバス停が1行に融合し、129組は県境すら
越える。`POLICY.md` §4 が禁じる「誤った 1:1 の捏造」そのものになるので、集約はしない。

### `p11_stop_id` は行の識別子であって、実体の同一性ではない

`docs/IDENTITY_MODEL.md` が定めるのは `address_id` —— ABR 町字の**永続的な同一性**であり、
`genesis_key` という**自然キーが存在すること**を前提に blake2s から鋳造され、衝突は警告では
なくビルド失敗として扱われる。バス停にはその前提が無い。非一意なタプルをハッシュしても
非一意な ID にしかならないので、この仕組みは適用できない。

一方、スキーマには自然キーを持たない行のための代理キーが既にある（`bridge_id`、`block_id`、
`coverage_id`）。`p11_stop_id` はその系列で、値は**発行元の県内レコード順**:

```
p11-22-{都道府県コード}-{連番:06d}      例: p11-22-13-000042
```

版を固定している限り決定的で、**座標を用いない**（`POLICY.md` §3.1 は座標をリリース成果物に
出すことを禁じている）。版をまたいで安定な識別子ではない、という点は `address_id` と対照的で
あり、意図的にそうしている。

座標まで一致する12組（24行）は発行元のデータにそのまま存在する重複で、**黙って片方を消す
ことはしない**。

## 3. 結合

バス停は**発行元が点そのものを与えている**ので、駅と違い代表点を導く余地が無い。よって
`build/busstop.py` には `placement_point` 列が無い —— 開示すべき選択が存在しないからである。
判定は `GridIndex` + `point_in_rings`（駅・メッシュと同じ実装）。

拒否の規則は駅と同一:

- どのポリゴンにも入らなければ `unresolved`。**最寄りには寄せない**（`POLICY.md` §4）。
- 2つに入れば `ambiguous`。候補を両方残す。
- 境界データ側のコードを jpac の現行市区町村が持たない場合、行は残し `lg_code` は NULL、
  5桁の `boundary_jis_city_code` を保持して追跡可能にする。
- 水面調査区（`HCODE` 8154）と抜け地（`KIGO_D` D1）は索引を作る前に除外
  （`estat.is_land_polygon`）。
- 点が取れないバス停も `unresolved` として行を残す。「形状が無い」と「どこにも入らない」は
  別の主張なので、前者を黙って消すと後者と区別できなくなる。

### 位置による突き合わせは、件数を検査してから信じる

各県の `.shp` と `.dbf` は**同じ順番**で対応する。`read_dbf` は削除レコードを飛ばすが `.shp`
は飛ばさないので、ズレうる。ズレても誰も気づかないまま全バス停が別の市区町村に結び付く
種類の誤りなので、県ごとに件数の一致を検査してから索引を信頼する
（`pipeline._read_p11_geometry`）。

実測: 47県すべてで一致し、**点が取れなかったバス停は 0**（geometry 278,515 = バス停数）。

## 4. 結果

| | 件数 |
|---|---:|
| bridge 行数 | 278,525 |
| 市区町村が1つに確定 (`contains`) | 278,390 |
| 候補が2つ (`ambiguous`) | 10停留所 / 20行 |
| どこにも入らない (`unresolved`) | 115 |
| `auto` | 277,172 |
| `review_required` | 1,353 |
| バス停のある市区町村 | **1,797** |

内訳は整合する: 278,390 + 20 + 115 = 278,525、277,172 + 1,353 = 278,525、
1,353 = 1,218（断面のズレ）+ 20 + 115。

### 断面のズレ 1,218行は、すべて旧浜松市の区

`lg_code` が NULL になる行は7つのコードだけから出ている。

| `boundary_jis_city_code` | 行数 |
|---|---:|
| 22131 | 287 |
| 22135 | 276 |
| 22133 | 171 |
| 22137 | 141 |
| 22134 | 129 |
| 22132 | 113 |
| 22136 | 101 |

2020年の境界データが持つ**旧浜松市の7区**で、2024年の区再編より前の断面である。駅のブリッジ
で54行が同じ理由で NULL になったのと**同一の事象**であり、バス停の数が駅より桁違いに多い
ぶん行数が増えているだけで、新しい問題ではない。現行コードへの読み替えは
`overrides/municipality_lineage.yml` にあり、`boundary_jis_city_code` を残してあるので
追跡できる。

なお、JIS コードが複数の現行 `lg_code` に対応するために除外されたコードは **0件**だった。

### 候補が2つになった10件は、本当に境界上にある

| バス停 | 事業者 | 候補 |
|---|---|---|
| マーケットシティ古河 | 古河市 | 08204 / 09364（茨城・栃木） |
| 高峰温泉（夏季） | ジェイアールバス関東 | 10425 / 20208（群馬・長野） |
| 湯河原峠 | 伊豆箱根バス | 14384 / 22325（神奈川・静岡） |
| 明神峠 | 富士急モビリティ | 22344 / …（静岡・山梨） |
| **県境** | 鹿児島交通 | 45202 / 46217（宮崎・鹿児島） |

名前が「県境」であるものが含まれているとおり、これは**データが正しいことの現れ**であって
解消すべき欠陥ではない。どちらかに決めず両方を残す。

### どこにも入らない115件

海岸・埋立地・境界データの隙間にあたるもの。例: 「道の駅うとろ・シリエトク」（知床の海岸）、
「県境」（岩手県北自動車）。**最寄りの市区町村には寄せない。**

## 5. しないこと

- **最寄りへの割り当てをしない。**（§3）
- **名前での集約をしない。**（§2）
- **町字には降りない。** e-Stat 小地域は jpac の町字より約3.1倍粗い（`POLICY.md` §4）。
- **座標をリリースに出さない。** 点はビルド時に読むだけで、成果物には入らない
  （`POLICY.md` §3.1）。
- **バス系統は取り込まない。** `P11_003_01..35` / `P11_004_01..35` の70列はファイルサイズの
  大半を占めるが、経路の属性であってこのプロジェクトが横断させる対象ではない。

## 6. ペイロードの扱い

このデータは他のソースと構造が違い、3点の対応が要った。

| 事実 | 対応 |
|---|---|
| shape type が **Point (1)** | `read_shp_shapes` は Polygon/PolyLine の1レイアウトしか解さなかった。点は bbox もパート表も持たない別構造なので分岐を追加（`tests/test_payload_shapes.py`） |
| 文字コードが **SJIS** | N02 と違い UTF-8 の複製が無い。`.cpg` を読んで期待値と照合する |
| DBF が全国で **4.81 GiB** | 73列すべてが `C 254` の固定長で、1レコード18,543バイト。実質99%が空白 |
| 圧縮比が**47県中38県**で既定上限200超（最大269.1） | 上限は**全体では緩めない**。`ArchiveLimits` が呼び出し単位の引数である設計を使い、P11 だけに 400 を与える（`P11_LIMITS`） |
| zip の**入れ子**（全国1ファイルの中に47県分） | `open_zip_bytes_safely` を追加し、入れ子でも `safe_zip_members` の検査を省かない |
